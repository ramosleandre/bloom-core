# Preuves du suivi Epitech

Bloom est suivi dans le cadre de l'EIP Epitech (Technical Track, 2026-27). Les fichiers de ce dossier sont tenus au fil de l'eau : chacun sert de preuve pour un objectif du suivi.

Objectifs : **O1** veille et problème dur · **O2** architecture structurée et fiable · **PERF** mesurer et optimiser la performance (objectif complémentaire D) · **EXP** travailler avec des experts techniques (objectif complémentaire C). Ces lettres n'ont rien à voir avec les blocs C et D du code.

| Fichier | Ce qu'il montre | Objectif |
|---|---|---|
| [`../hard-problem.md`](../hard-problem.md) | le problème dur, ses critères chiffrés, puis le résultat avant / après | O1 |
| [`research-setup.md`](research-setup.md) | le dispositif de veille : sources, outils, rythme, répartition | O1 |
| [`research-log.md`](research-log.md) | le journal de veille, avec une conclusion par entrée | O1 |
| [`presentations.md`](presentations.md) | les présentations internes, et ce qui a été repris dans le projet | O1 |
| [`community.md`](community.md) | les contributions aux communautés techniques | O1 |
| [`../adr/`](../adr/) | les décisions d'architecture | O2 |
| [`regressions.md`](regressions.md) | les régressions attrapées par les tests, les PR bloquées par la CI | O2 |
| [`reviews.md`](reviews.md) | les reviews qui ont fait changer une PR | O2 |
| [`tech-debt.md`](tech-debt.md) | la dette assumée, la qualité mesurée, les règles désactivées | O2 |
| [`reproducibility.md`](reproducibility.md) | l'installation du projet par une personne extérieure | O2 |
| [`perf.md`](perf.md) | l'axe de performance, ses indicateurs, l'historique des mesures et des optimisations | PERF |
| [`experts.md`](experts.md) | les sujets soumis à des experts, et ce qu'on en a fait | EXP |

Ailleurs dans le dépôt : les mesures brutes dans `lab/results/`, les rapports de qualité datés dans `lab/results/quality/`, l'historique de la CI dans l'onglet Actions.
