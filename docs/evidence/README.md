# Epitech follow-up evidence

Bloom is followed as part of the Epitech EIP (Technical Track, 2026-27). The files in this folder are kept up to date as work goes on: each one serves as evidence for an objective of the follow-up.

Objectives: **O1** tech watch and hard problem · **O2** structured and reliable architecture · **PERF** measure and optimize performance (complementary objective D) · **EXP** work with technical experts (complementary objective C). These letters have nothing to do with blocks C and D in the code.

| File | What it shows | Objective |
|---|---|---|
| [`../hard-problem.md`](../hard-problem.md) | the hard problem, its quantified criteria, then the before / after result | O1 |
| [`research-setup.md`](research-setup.md) | the tech watch setup: sources, tools, cadence, split of work | O1 |
| [`research-log.md`](research-log.md) | the research log, with a conclusion per entry | O1 |
| [`presentations.md`](presentations.md) | internal presentations, and what was adopted in the project | O1 |
| [`community.md`](community.md) | contributions to technical communities | O1 |
| [`../adr/`](../adr/) | architecture decisions | O2 |
| [`regressions.md`](regressions.md) | regressions caught by tests, PRs blocked by CI | O2 |
| [`reviews.md`](reviews.md) | reviews that changed a PR | O2 |
| [`tech-debt.md`](tech-debt.md) | accepted debt, measured quality, disabled rules | O2 |
| [`reproducibility.md`](reproducibility.md) | installation of the project by an outsider | O2 |
| [`perf.md`](perf.md) | the performance axis, its indicators, the history of measurements and optimizations | PERF |
| [`experts.md`](experts.md) | topics submitted to experts, and what we did with them | EXP |

Elsewhere in the repository: raw measurements in `lab/results/`, dated quality reports in `lab/results/quality/`, CI history in the Actions tab.
